# Rust runtime: начальная проверка

Проверка от 2026-11-15. Установлен Homebrew rustc/cargo 1.100.0 и соответствующие
исходники библиотеки по `rustc --print sysroot`. Новые toolchain не устанавливались.

## Ограничение официального target

`rustc --print cfg --target aarch64-nintendo-switch-freestanding` выдаёт
`target_os="horizon"`, `target_vendor="nintendo"`, без `target_family="unix"`.
В [target spec Rust 1.100.0](https://github.com/rust-lang/rust/blob/1.100.0/compiler/rustc_target/src/spec/targets/aarch64_nintendo_switch_freestanding.rs)
явно стоит `std: Some(false)`.

В установленном rust-src проверены ветвления в `library/std/src/sys/`:
`pal/mod.rs`, `fs/mod.rs`, `thread/mod.rs`, `net/connection/mod.rs`.
Для этой комбинации cfg выбираются реализации `unsupported`, а не Unix backend.
Следовательно, успешная сборка `core` не предоставляет Horizon готовые
`std::fs`, `std::thread` и `std::net`.

Существуют проекты с адаптированным std/newlib, например
[FlashNX](https://github.com/Jonathan8520/FlashNX/blob/main/DEVELOPMENT.md).
Его документация показывает гибрид C++/Rust, собственные мосты и исправления std.
Совместимость этих исправлений с Rust 1.100.0 и Horizon пока не проверена;
их нельзя считать готовым runtime для этого порта.

## Выполненный эксперимент

Собрана собственная библиотека `#![no_std]`, использующая только `core`.
Экспорт `craftrustnx_rust_mix(u64) -> u64` связывается с devkitA64 C-приложением.
Проверяются четыре фиксированных вектора (ноль, единица, максимум u64, старший бит),
затем на каждом кадре — значения, зависящие от счётчика кадров, кнопок и стиков,
с независимым вызовом Rust-функции и сравнением с C-вычислением.
На экране показываются PASS/FAIL, общее число проверок и число ошибок.
При panic библиотека вызывает C `abort`; unwind через границу ABI не используется.
На Switch Lite пользователь подтвердил 2000 checks и 0 errors (2026-11-15).

Сборка ограничена установленными исходниками/кешами Cargo: `--offline --locked`,
один job, release без debug/LTO, CPU Cortex-A57, PIC, `panic=abort`.
Ограничения места проверяются до и после сборки. Это не непрерывная квота диска;
полный Horizon этим скриптом не собирается.

## Что ещё требуется

После аппаратного ABI PASS отдельно проверен std/newlib backend: аллокатор, TLS,
потоки/синхронизация и время (результат ниже). Файлы/каталоги, DNS, сокеты,
источник случайных чисел и HTTPS ещё требуют проверки.
Альтернатива — явные платформенные обёртки через C/libnx с последовательной
адаптацией зависимостей Horizon; стоимость такого переноса пока не оценена.

Для ближайшего сетевого теста нужен только status ping Java Edition (MOTD и версия),
без входа в игровой мир. Он не доказывает offline login или совместимость gameplay.
Offline-профили остаются обязательным требованием полноценного клиента.

## FlashNX: проверка механизма сборки std

Исследован commit `97085c65`:
[Rust config](https://github.com/Jonathan8520/FlashNX/blob/97085c65/rust/.cargo/config.toml),
[patch-rust-src.sh](https://github.com/Jonathan8520/FlashNX/blob/97085c65/scripts/patch-rust-src.sh),
[net.rs](https://github.com/Jonathan8520/FlashNX/blob/97085c65/rust/src/net.rs).
Конфигурация вручную включает `unix`, `target_family="unix"` и `target_env="newlib"`
поверх штатного Switch target. Также включены native TLS и сборка std/panic_abort.
Скрипт правит установленный rust-src; в нашем проекте этот скрипт не выполняется.

В конфигурации отмечен сбой TLS при panic на рабочем потоке. Правка RandomState
обходит один путь через TLS, но это не доказательство исправности всей std.
Сетевой модуль передаёт HTTPS-запросы в C++ через FFI; наличие этого модуля
не подтверждает работу `std::net`.

Локальный libc 0.2.189 содержит `unix/newlib/horizon/mod.rs` с комментарием
`ARMv6K Nintendo 3DS C Newlib definitions`, `sockaddr.sa_data[26]` и
`sockaddr_storage` из family и 26 байт padding. Это подтверждает необходимость
сверки с Switch ABI, а не предположение о совместимости по имени `horizon`.
Для принятия остальных выводов исследования нужны измерения установленными
devkitA64 headers и сверка с локальным libc: `stat`, `dirent`, семейство `sockaddr`.
Ошибки layout нельзя проверять вызовами функций с заведомо несовместимыми буферами:
такой тест может испортить память вместо возвращения предсказуемого FAIL.

На этом этапе исследования следующим шагом были размеры, выравнивания и смещения полей
из C-компилятора без выполнения кода на консоли. std тогда ещё не собиралась.
Для последующего std-прототипа требовались согласованные ABI и проверка места:
оценка исходного исследования 0.3–0.8 GiB не гарантирует соблюдение лимита 512 МиБ.

## Измеренный C ABI

`bash tools/switch-abi-audit/run.sh` повторно выполнен Codex: exit 0,
69 записей из ELF-секции, 1680 байт. Исполняемый код на консоли не запускался.
Использованы существующий образ devkitA64 и его libnx/newlib headers, без сети.

Подтверждены C-размеры/выравнивания: `sockaddr_storage` 128/8,
`sockaddr` 16/1, `sa_family_t` 1/1; `stat` 104/8 со `st_size` по смещению 16;
`dirent` 260/2, `d_name` по смещению 3. Текущий отчёт сравнивает их с
**вычисленными по исходникам**, а не измеренными Rust layouts.
Например, модель Rust даёт `sockaddr_storage` 28/2, `stat.st_size` на 24.
Совпадения полного размера структуры недостаточно для ABI-совместимости.

Перед созданием локального libc-патча следующий шаг — извлечь аналогичные
константы настоящим Rust-компилятором из локального libc без std и сверить
таблицы. Это отделит реальные несовпадения от возможных ошибок модели парсера.

## Измеренный Rust ABI

Теперь добавлен `tools/switch-abi-audit/rust/run.sh`: установленный Rust 1.100.0
компилирует `size_of`/`align_of`/`offset_of!` для **неизменённого** libc 0.2.189
в ELF-секцию, которая извлекается без выполнения target-кода. Включены только
процессные cfg `unix`, `target_family="unix"`, `target_env="newlib"`; собирается
core, без std. Конечный объект проверяется как ELF64 little endian AArch64.

Из 69 записей: размеры/выравнивания совпали у 15 из 28 типов;
смещения — у 18 из 35 измеренных полей. Получены 30 несовпадений и 6 явно
неизмеренных C-only полей. Это подтверждает основные выводы предыдущей модели.
`sockaddr_storage` действительно 28/2 против C 128/8, `stat.st_size` находится
на 24 вместо 16. Несовместимы также измеренные pthread-типы.

Кеш Rust теперь занимает около 403 МиБ, общий лимит остаётся 512 МиБ.
До новой конфигурации компилятора нужно оценивать повторную сборку core,
чтобы не создать ещё один его большой кеш. На host остаётся около 17 GiB.

Проектный патч libc теперь проходит строгую компиляционную проверку:
28/28 размеров/выравниваний и 41/41 смещений, без пропущенных полей.
Исходники Cargo registry и установленного rust-src остаются неизменными.
Проверены знаковость изменённых typedefs, C-инициализаторы mutex/cond и дополнительные
asserts для sockaddr_in6. Патч ограничен aarch64/horizon/newlib; определение 3DS
сохранено. Скрипт staging разрешает удаление только собственной помеченной копии
в каталоге generated build.

Codex проверил `nm --defined-only` для
`devkitA64/aarch64-none-elf/lib/pic/libsysbase.a`: определены `pthread_create`,
`pthread_key_create`, `pthread_mutex_lock`, `pthread_cond_wait`,
`__libc_lock_acquire`. Отсутствие символов в `libnx.a` или stub `libpthread.a`
не означает отсутствия их в toolchain: для следующего прототипа нужен libsysbase.
Это всё ещё не проверка работы потоков на устройстве.

Даже совпадение этой таблицы не подтверждает всё libc: отдельно потребуются
остальные константы/инициализаторы, сигнатуры вызовов, TLS и аппаратные проверки.

## std: сборка и линковка выполнены

Новый platform/switch/std-probe использует проектный JSON target (unix/newlib,
без native ELF TLS) и локальную подмену registry source. По unit graph проверено,
что и сама std собирается с ABI-исправленной libc: простого [patch.crates-io]
для этого в проверенной конфигурации оказалось недостаточно. Взяты установленные
rust-src/vendor, без изменения системных файлов, загрузок и фиксированных RNG keys.

Перед сборкой удалены только три obsolete core cache из нашего target, сохранены
NROs/ABI evidence. Оценка бюджета больше не превращается в ноль при отсутствии
кеша: используется floor 128 МиБ на core unit, а имеющаяся std учитывается
как уже построенная часть бюджета. Новая std занимает около 213 МиБ.

Сборка и линковка отдельного NRO прошли. Потребовался C-адаптер sysconf(_SC_PAGESIZE),
который сообщает 4096; номер query сверяется в Rust и C, остальные query unsupported.
[libnx threadCreate](https://github.com/switchbrew/libnx/blob/master/nx/source/kernel/thread.c)
использует ту же 0x1000 alignment для стека. Выбор pthread-key TLS — экспериментальная
конфигурация; отсутствие TLS-секций в JSON script не доказывает невозможность
native TLS при финальной линковке C-приложения собственным script libnx.

Шесть runtime checks вызываются из C по одному и возвращают requested/passed/failed
маски с подписью. Неизвестные младшие биты дают FAIL, непредставимые старшие биты
отвергаются (нулевая подпись). Повторный main-thread TLS check сбрасывает свой slot.
Проверена логика на host. Пользователь подтвердил PASS всех шести проверок
на Switch Lite 2026-11-15: ALLOC, TIME, TLS main, THREAD spawn/join,
SYNC mutex/condition и TLS worker destructor. Это подтверждает эти базовые
операции выбранной конфигурации runtime; длительная стабильность ещё не проверена.
getrandom, файлы, сеть и прочие ABI/семантика libc этим этапом не проверены.
