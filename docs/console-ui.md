# Условное требование: консольный интерфейс

Пользователь указал [Lasting-Legacy/LCE-Monorepo](https://git.nostalgica.net/Lasting-Legacy/LCE-Monorepo)
как ориентир интерфейса. Интеграция нужна только при сохранении подключения
к обычным Java-серверам без установки этого мода на сервер. Если такое подключение
невозможно, интеграция мода исключается. Базовая совместимость с Java-серверами
имеет приоритет над сходством интерфейса.

Это дополнение к нативному порту Horizon на Switch Lite; оно не заменяет работу
над runtime, графикой, управлением и offline-профилями.

После исследования пользователь выбрал **Legacy4J** как конкретный ориентир
интерфейса. Дальнейшая работа по UI ориентируется на Legacy4J отдельно от
LCE-модпака. Условие совместимости с vanilla-серверами и проверка происхождения
каждого импортируемого ресурса сохраняются.

## Что известно

Страница указанного репозитория описывает его как архивный monorepo модпаков,
ресурспаков и датапаков, а не как один UI-мод. На странице указан размер 1.8 GiB;
полный репозиторий и submodule не загружаются из-за лимита диска.
README предупреждает о разных лицензиях отдельных пакетов. Лицензия monorepo
не принимается за разрешение использовать все текстуры и остальные ресурсы.

## Проверка перед реализацией

1. Установить конкретный UI-мод, его версию и исходный репозиторий.
2. Проверить обязательные зависимости, handshake и custom payloads: они должны
   допускать обычный vanilla Java-сервер. Проверить UI отдельно от gameplay-модов
   в составе модпака. Итоговый клиент проверить рядом с обычным Java-клиентом.
3. Проверить отдельные LICENSE/NOTICE для кода и каждого набора ассетов,
   авторство и ограничения сторонних/Minecraft-ресурсов. Сейчас ничего не копируется.
4. Подтвердить применимость к поддерживаемым версиям протокола Horizon.

Java/Fabric/NeoForge-мод не загружается непосредственно в Rust-клиент Horizon.
Для такого UI потребуется нативная реализация и, при разрешающей лицензии,
выборочное переиспользование ресурсов. Наличие ресурспака само по себе не
реализует консольную навигацию или сетевую совместимость.

Минимальные сетевые критерии: vanilla status/login/configuration/play без
обязательного ответа мода на сервере; сохранение offline-входа там, где он разрешён,
и Microsoft-входа на `online-mode=true`; обычные перемещения, инвентарь и действия
не требуют новых серверных пакетов. Модифицированные gameplay-механики не
включаются в этот интерфейсный перенос.

## Результат исследования (2026-11-15)

UI реализует **Legacy4J**, а не весь LCE-модпак. Проверен
[Legacy-Minecraft commit f49505da](https://github.com/Wilyicaro/Legacy-Minecraft/tree/f49505da),
версия 1.9.1 по `gradle.properties`. В
[Legacy4JClient.java](https://github.com/Wilyicaro/Legacy-Minecraft/blob/f49505da/src/main/java/wily/legacy/Legacy4JClient.java)
при открытии крафта используется проверка `hasModOnServer()`, а при её отсутствии
есть fallback к обычному `InventoryScreen`. Это подтверждает наличие клиентского
пути без серверного UI, но не заменяет тест соединения с vanilla-сервером.
Сам мод также содержит серверные функции; целый модпак переноситься не будет.

**Решение: условно принять Legacy4J как ориентир для нативного интерфейса.**
Переносятся только представление меню/HUD и навигация с контроллера, сохраняющие
vanilla-семантику. Инвентарь/крафт должны работать через обычные серверные окна
и пакеты поддерживаемой версии Java; LCE-окна, требующие custom payloads,
Host Options и серверные gameplay-изменения исключаются. Если элемент невозможно
реализовать без серверной зависимости, он получает vanilla fallback либо исключается.
Это не обещание полной функциональности Legacy4J.

В [gradle.properties](https://github.com/Wilyicaro/Legacy-Minecraft/blob/f49505da/gradle.properties)
указана LGPL-3.0-or-later, а
[LICENSE.md](https://github.com/Wilyicaro/Legacy-Minecraft/blob/f49505da/LICENSE.md)
содержит LGPLv3. Метаданные сторонних страниц не заменяют лицензию исходников.
[README](https://github.com/Wilyicaro/Legacy-Minecraft/blob/f49505da/README.md)
отдельно указывает авторов встроенных пакетов, How-To-Play текста, шрифта и иконок.
Поэтому лицензия кода не принимается за разрешение на все встроенные ресурсы.
Список разрешённых к копированию ассетов пока пуст: LCE-извлечённые и неясные
сторонние ресурсы не включаются. При выборе конкретного файла нужно записать
источник, commit, автора, лицензию и требуемые уведомления до его импорта.

Подключение к vanilla/Paper/прокси и поведение античитов ещё не тестировались;
поддержку отдельных Java-версий определяет протокол Horizon. Разработка самого
интерфейса начнётся после работоспособности runtime и графического вывода.

Статус: нативный UI условно принят как цель; Java-мод и его ассеты не интегрированы.
